# MCP справочника

MCP предоставляет **только поиск и чтение** протоколов и знаний. Пользовательских
инструментов записи, импорта или ручного обновления нет. Локальный кеш обновляется
автоматически самим процессом.

## Запуск

Требуются Node.js 24 и Git для режима репозитория.

После публикации в npm запуск не требует клонирования репозитория:

```bash
npx --yes @l2ce/dev-reference-mcp
```

В npm публикуется только MCP. Локальные `@l2ce/core` и `@l2ce/database`
включены в его архив; нативный `better-sqlite3` устанавливается под вашу платформу.

Настройка stdio в MCP-клиенте:

```json
{
  "mcpServers": {
    "l2ce": {
      "command": "npx",
      "args": ["--yes", "@l2ce/dev-reference-mcp"]
    }
  }
}
```

Для фиксированной версии укажите `@l2ce/dev-reference-mcp@0.1.0`.
Первый ручной релиз и последующие публикации через CI описаны в
[руководстве релизов](../../docs/development/releases.md).

Запуск из исходников:

```bash
pnpm --filter @l2ce/dev-reference-mcp... build
node apps/mcp/dist/index.js
```

По умолчанию источник — `https://github.com/l2ce/dev-reference.git`, удалённый HEAD,
каталог `packages/database/data`. Транспорт — stdio: stdout содержит только
сообщения MCP, диагностики запуска направляются в stderr.

```bash
node apps/mcp/dist/index.js --repository https://github.com/l2ce/dev-reference.git --branch main --poll-interval 60
```

Для разработки используется локальная папка экспорта:

```bash
node apps/mcp/dist/index.js --data-dir packages/database/data --cache-dir /tmp/opencode/protocols-mcp
```

| Параметр          | Переменная окружения      | Назначение                           |
| ----------------- | ------------------------- | ------------------------------------ |
| `--repository`    | `PROTOCOLS_REPOSITORY`    | Git-источник                         |
| `--branch`        | `PROTOCOLS_BRANCH`        | Ветка; без параметра удалённый HEAD  |
| `--data-path`     | `PROTOCOLS_DATA_PATH`     | Папка внутри репозитория             |
| `--data-dir`      | `PROTOCOLS_DATA_DIR`      | Локальный режим вместо Git           |
| `--cache-dir`     | `PROTOCOLS_CACHE_DIR`     | Корень приватного кеша MCP           |
| `--poll-interval` | `PROTOCOLS_POLL_INTERVAL` | Интервал в секундах, по умолчанию 60 |

Кеш по умолчанию находится в `$XDG_CACHE_HOME/l2ce-protocols` либо
`~/.cache/l2ce-protocols`. Разные источники изолированы. Кеш не может находиться
внутри локальной папки-источника.

## Инструменты

| Инструмент           | Основные параметры                                                  | Результат                                          |
| -------------------- | ------------------------------------------------------------------- | -------------------------------------------------- |
| `get_project_info`   | —                                                                   | Назначение и версия сервера                        |
| `list_catalog`       | `collection`, `branch?`, `chronicle?`, `locale?`                    | Ветки, хроники или выпуски                         |
| `list_protocols`     | `query?`, `number?`, `branch?`, `chronicle?`, `release?`, `locale?` | Краткие карточки протоколов                        |
| `get_protocol`       | `protocol`, `locale?`                                               | Выбранный протокол, выпуски, регионы, Login-номера |
| `search_knowledge`   | `protocol`, `locale?`, `query?`, `kind?`, `server?`, `direction?`   | Применимые знания; без query — список              |
| `read_knowledge`     | `protocol`, `keys`, `locale?`                                       | Несколько документов одним снимком                 |
| `get_dataset_status` | —                                                                   | Состояние активной базы и фонового обновления      |

Каталог и поиск поддерживают `limit` (1–100), `offset`, возвращают `nextOffset`.
Поиск также принимает `status`: `missing`, `partial` или `documented`.
`list_catalog.collection`: `branches`, `chronicles`, `chronicle-releases`.
У `read_knowledge.keys` от 1 до 50 адресов вида `packet:key-packet`,
`scenario:game-connection`, `article:game-framing`.

Протокол задаётся читаемым ключом: `273`, `152-rev-1` или `protocol:152-rev-1`.
Поиск по `number: 152` возвращает все соответствующие контексты.
Если язык не указан, используется основной язык базы; другой перевод не подставляется.

Документы содержат исходный Markdown, источники, технические признаки, статусы и
открытые вопросы. `availability` различает `available`, `not-found`, `unmapped`,
`translation-missing`. Неизвестный протокол — ошибка всего запроса. Внутренние
Markdown-директивы возвращаются буквально; их ключи пригодны для следующего чтения.

Ответы содержат `revision` предметного снимка и `sourceHash`. Все результаты
одного запроса относятся к одному поколению. Ресурсы `protocols://project` и
`protocols://dataset` доступны только для чтения.

## Автоматическое обновление

1. Проверить коммит выбранной удалённой ссылки.
2. При новом коммите получить метаданные Git с фильтром `blob:none` и определить
   tree hash папки `data/`.
3. Если tree hash прежний, сохранить сведения о проверенном коммите без checkout
   и повторного импорта базы.
4. Если hash изменился, выполнить sparse checkout папки из закреплённого коммита.
5. Импортировать снимок в отдельный SQLite-файл и проверить его целиком.
6. Открыть новое поколение read-only, сохранить указатель кеша и переключить чтение.

Tree hash учитывает содержимое файлов: правка Markdown обнаруживается и при
неизменных именах и количестве строк. Изменения README вне `data/` не перезагружают
базу. В локальном режиме аналогом служит SHA-256 путей и байтов файлов.

Запросы используют неизменяемое представление активного поколения. Уже начатый
запрос не смешивает старые и новые данные. Одновременные проверки объединяются.
При сетевой ошибке или невалидном снимке остаётся последняя рабочая база,
а `lastError` содержит причину. После перезапуска проверенный кеш доступен сразу;
его актуальность проверяется в фоне. Без кеша первая успешная загрузка обязательна.

`get_dataset_status` показывает:

- `sourceHash` — хеш каталога-источника;
- `sourceCommit` — закреплённый Git-коммит;
- `dataRevision` — SHA-256 предметных данных активной SQLite-базы;
- `checkedAt`, `lastError`, `updating` — состояние фоновой проверки.

Предыдущие файлы поколений сохраняются в приватном кеше. Источник и рабочая база
разработчика не изменяются. Каждый экземпляр MCP имеет собственный временный
sparse checkout, поэтому параллельные процессы не меняют файлы во время чужого импорта.
Закрытие транспорта останавливает таймер, освобождает read-only соединение и удаляет
свой checkout после завершения выполняющейся проверки.

Проверки: `pnpm --filter @l2ce/dev-reference-mcp typecheck`,
`pnpm --filter @l2ce/dev-reference-mcp test`.
