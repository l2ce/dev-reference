# Архитектурный профиль Web

Профиль действует в `apps/web/src`. Он уточняет
[Next.js Reference](../../.agents/skills/nextjs-reference/SKILL.md)
для Next.js App Router и статического экспорта. Инварианты
[Unit Architecture](../../.agents/skills/unit-architecture/SKILL.md) обязательны.

## Слои и фасеты

Алиасы `app/*`, `compositions/*`, `domains/*`, `infra/*`, `ui/*`, `shared/*`
соответствуют одноимённым каталогам `src/`. Межюнитные импорты идут через алиас
и фасет; внутренние импорты относительные. Группы композиций и словарь сегментов
определены архитектурным профилем Next.js Reference. Пустые слои и фасеты не создаются.
Локальный перечень маркеров фасетов закреплён ниже: он сохраняет используемый
`lazy.ts`; отдельный `browser.ts` в этом приложении не принят.

Маркеры зарезервированы во всём frontend root:

| Маркер      | Назначение                                                                        |
| ----------- | --------------------------------------------------------------------------------- |
| `index.ts`  | Универсальный API: типы, чистые функции и совместимые с обеими средами компоненты |
| `server.ts` | API сборочного Node.js/RSC-графа; защищён импортом `server-only`                  |
| `client.ts` | Клиентская React-граница с `'use client'`, совместимая с prerender                |
| `lazy.ts`   | Минимальный API динамического импорта; только при фактической потребности         |

Фасеты содержат директивы и реэкспорты, но не реализацию. Универсальный фасет
не реэкспортирует средовые. Один исполняемый экспорт публикуется в одном фасете.
Server Component может подключать компонент через `client.ts`, но не вызывать
его хуки. Клиентский граф не достигает `server.ts`, SQLite или Node.js API.

## Владельцы

- `app`: framework-файлы, URL, метаданные, `generateStaticParams`, HTML-оболочка
  и подключение готовых провайдеров/композиций. Здесь нет продуктовой вёрстки.
- `compositions`: каркас, экраны каталога, протокола, документа и 404;
  локальное состояние фильтра принадлежит каталогу.
  `MainLayout` владеет общей внешней шириной страниц и боковыми полями по тем же
  токенам, что шапка; вложенные экраны не задают второй внешний контейнер.
- `domains/reference`: чтение одного снимка базы через `ReferenceReader`,
  сбор полных списков, адаптация директив к точному протоколу и языку.
- `domains/contributors`: проверка публичных профилей GitHub, полный список участников
  проекта и часовой кеш сборочного чтения.
- `infra/github-api`: сгенерированная REST-операция участников, серверный транспорт,
  тайм-аут и технические ошибки GitHub.
- `infra/site-config`: типизированная конфигурация публикации.
- `infra/browser-location`: подписка на query URL и сохранение фильтров через History API.
- `ui/themes`: Mantine, общие стили и жизненный цикл цветовой схемы.
- `ui/markdown`: отображение подготовленного Markdown, без выбора редакций.
- `shared/lib/value-predicates`: чистые проверки runtime-формы.
- `shared/localization`: поддерживаемые коды языков и их проверка.

Словари подписей находятся в `config/` своего владельца. Правила TypeScript,
React-компонентов и CSS принадлежат `ts-styleguide`, `tsx-styleguide` и
`postcss-styleguide` из [профиля знаний проекта](../../docs/development/skills.md).
Публичные props размещаются в `types/` компонента; существующие базовые предикаты
доступны через `shared/lib/value-predicates`.

## Интеграция Next.js и статический экспорт

Next.js заменяет Vite, `createRoot` и React Router. Framework-файлы только
подключают публичные API и подпадают под системное исключение генерации TSX.
Все продуктовые TSX, включая внутренние компоненты и провайдеры, создаются
`pnpm run create` из локальных шаблонов.

Dev и build используют Webpack. В Next.js 16.4.3 стандартный matcher
`serverExternalPackages` не распознаёт реальные пути pnpm workspace symlinks
в `packages/`; при bundling ломается package-relative `import.meta.url` базы.
`next.config.ts` явно оставляет используемые API базы/Core внешними только
для server build. Node.js 24 загружает их нативно, сохраняя SQLite и пути пакетов.
Основание: [Webpack configuration](https://nextjs.org/docs/app/api-reference/config/next-config-js/webpack).

Экран, читающий базу, публикуется через `server.ts`. Подготовленные данные
передаются интерактивным блокам через сериализуемые props. `ThemeProvider`
принимает серверное поддерево через `children`, не импортируя его.

Первый визит следует системе; явная светлая или тёмная тема хранится в localStorage.
Универсальный `ThemeBootstrap` подключается в head: синхронный локальный inline script
меняет только CSSOM-правило `color-scheme` до разбора body. Содержимое DOM и атрибуты
html остаются одинаковыми для серверного рендера и гидратации. CSS `light-dark()`
и публичный Styles API Input используют эту нативную палитру, поэтому временный
системный атрибут Mantine не меняет вид страницы. Клиентский manager восстанавливает
настройку в lifecycle и обновляет CSSOM при действии пользователя.
Это предотвращает вспышку системной темы при противоположном сохранённом выборе.
ColorSchemeScript, ожидание mount и `suppressHydrationWarning` не используются.

Локализованные ветки имеют собственный root layout, чтобы `html[lang]`
соответствовал URL. Английские страницы используют ветку без префикса, русские — `/ru/`. Общий
`app/document.tsx` соединяет HTML, публичный Provider и MainLayout.
`global-not-found.tsx` обслуживает общий статический 404 при нескольких
root layouts; для этого включён документированный `globalNotFound`.

Основания: [Server/Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components),
[Static Exports](https://nextjs.org/docs/app/guides/static-exports),
[Global not found](https://nextjs.org/docs/app/api-reference/file-conventions/not-found).

## Данные и проверки

SQLite открывается read-only, снимок читается согласованно, соединение закрывается.
Сборка использует неизменяемый reader в пределах процесса; dev читает актуальную
базу при новом рендере. Все страницы перечисляются с полным обходом пагинации.
Ошибки базы останавливают сборку; отсутствие перевода остаётся предметным исходом.
Неполные знания не дополняются другим протоколом или языком.

Кеш задачи web build отключён: рабочий SQLite вне Git может измениться независимо
от исходников. CI предварительно импортирует снимок, локальная сборка читает рабочую базу.

`architecture:check` проверяет фасеты, матрицу слоёв, вложенность, циклы и
клиентский транзитивный граф. Проверка не доказывает смысловую корректность
владельца: она дополнительно проверяется на ревью. Обязательны lint, typecheck,
тесты контрактов, production export и проверка браузером по AGENTS.md.
