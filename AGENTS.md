# Назначение проекта

Принятые решения модели и пользовательские пути: [docs/README.md](docs/README.md).
Исследования находятся в `docs/research/`; исторические предложения в них
не заменяют действующие контракты из `docs/architecture/` и руководства базы.

L2CE Dev Reference — открытый справочник взаимодействия клиентов Lineage II с серверами.
Основная единица — профиль конкретной версии клиента с каркасом исследования обмена.
Сначала изучаются соединения, framing, кодирование, шифрование и сценарии; затем
постепенно добавляются опкоды, поля пакетов и поведение клиента.

- Сайт должен вести к протоколам и механизмам обмена. Инструкции по разработке
  справочника находятся в разделе для участников и README.
- Источник истины — таблицы SQLite в `packages/database/.local/database.sqlite`.
  `packages/database/data/` — генерируемый JSON-снимок импорта/экспорта и хранения в Git,
  не место ручного редактирования знаний. Предметная модель определяется таблицами.
  Сайт и MCP получают согласованные представления одной базы.
- Реализованная матрица таблиц описана в `docs/architecture/table-matrix.md`.
  В SQL хранятся code/number/variant/rev и предметные FK; публичные ключи и пути экспорта вычисляются.
  Предметные записи общие для языков; Markdown и источники принадлежат отдельным переводам.
  Импорт и экспорт принадлежат мини-CLI пакета базы:
  `pnpm run database import|export`. Импорт сам создаёт актуальную SQL-структуру;
  история миграций не ведётся. Рабочая база в Git не включается.
- Не заполняйте пробелы догадками или переносом данных из соседней ревизии.
  `missing`, `partial`, `null` и открытые вопросы — нормальное состояние исследования.
- Login revision, game revision, ветка игры, регион и сборка — разные признаки.
- У фактов должны быть конкретные источники. Не выдавайте описание эмулятора за
  проверку официальным клиентом. Таблица ревизий не подтверждает форматы пакетов.
- При изменении контрактов обновляйте валидатор, схемы, MCP, генерацию сайта и
  руководство `packages/database/README.md` согласованно.
- Генерируемые `dist/`, `build/`, `reference/` не редактируются вручную.
- Проверки: `pnpm data:build`, `pnpm typecheck`, `pnpm test`, `pnpm build`,
  `pnpm format:check`. Для изменений контрактов нужны проверки неполных записей,
  ссылок и различий профилей; массовое наполнение не требуется.

## Знания проекта

- Набор skills и их область действия закреплены в [профиле знаний](docs/development/skills.md).
  Skills установлены локально в `.agents/skills/` и относятся к этому репозиторию.
- Перед написанием, содержательным изменением или ревью TypeScript загрузите
  [ts-styleguide](.agents/skills/ts-styleguide/SKILL.md). Его каноны обязательны
  для нового и содержательно изменяемого кода приложений и пакетов.
- Правила веб-разработки и подключение профильных skills определяет `apps/web/AGENTS.md`.
- Форматирование и проверка типов дополняют проверку соблюдения skills.

## Браузерная проверка сайта

- Используйте установленный в проекте `agent-browser` для проверки интерфейса,
  навигации, локализации и генерации страниц `apps/web`.
- Конфигурация — `agent-browser.json`, запуск из корня — `pnpm browser`.
- Перед работой с сайтом прочитайте `apps/web/AGENTS.md`: там описаны запуск,
  адреса страниц, сценарии проверки и формат отчёта.
