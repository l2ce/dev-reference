# База данных

`@l2ce/database` хранит протоколы, пакеты, сценарии, статьи и их переводы в SQLite.
Архитектура проекта: [обзор и контракты](../../docs/architecture/README.md).
Сущности и связи: [предметная модель](../../docs/architecture/domain-model.md),
[матрица таблиц](../../docs/architecture/table-matrix.md).

## Файлы

Пакет остаётся приватным workspace-пакетом. При публикации MCP его `dist/`
(JavaScript, типы и JSON Schema) и `schema.sql` включаются внутрь MCP-архива.
Рабочая база и JSON-снимок в архив не входят; MCP создаёт собственный кеш.
Порядок публикации: [руководство релизов](../../docs/development/releases.md).

- `src/sqlite/schema.ts` — определения таблиц и ограничений.
- `schema.sql` — SQL, сгенерированный из этих определений.
- `.local/database.sqlite` — рабочая база, источник истины.
- `data/` — экспорт всех таблиц для хранения в Git и обмена.

`data/manifest.json` перечисляет таблицы, колонки, первичные ключи и число строк
снимка. Полная структура с типами и ограничениями находится в SQL-схеме.

Первичное наполнение каталога из исследовательских референсов и его ограничения
описаны в [отчёте о наполнении](../../docs/research/catalog-population.md).
Моковые пакеты, сценарии и статьи удалены; их форматы не выводятся из таблиц номеров.

Протоколы первоначально группируются по игровому номеру (`variant: 0`).
Суффикс `-rev-N` добавляется только при установленных различиях пакетного контракта
под одним номером. Разные страны, ветки и выпуски не создают варианты автоматически:
они могут ссылаться на одну запись. Совпадение номера при этом не доказывает
совместимость форматов пакетов; неопределённость сохраняется в открытых вопросах.

## Работа с базой

### Региональные контексты — схема 20

Выпуск хроники и региональный контекст — разные записи. Новые коллекции:
`regions`, `countries`, `release-contexts`. Ключ контекста имеет вид
`chronicle:high-five:base:na`; `code` уникален внутри выпуска, не внутри региона.

Контекст хранит `releaseKey`, nullable `regionKey`, nullable `releasedOn`,
`countryKeys`, `protocolKeys`, `order`, `status`, `translations`. Даты принимают
`YYYY`, `YYYY-MM`, `YYYY-MM-DD`; неверные календарные даты отклоняются.
Регион, дата и страны требуют источника хотя бы в одном переводе. NA/EU/RU/KR —
метки региональных сервисов, не языки перевода и не автоматические перечни стран.

Прямой `protocolKeys` выпуска хранит лишь неуточнённые по контексту связи.
`ReferenceReader` объединяет их с региональными контекстами и отдельно возвращает
`unscopedProtocolKeys`. Регионы протокола вычисляются по контекстам, а не
редактируются в протоколе. `protocol_regions` удалена.

```bash
pnpm cli regions list
pnpm cli contexts list --release high-five:base
pnpm cli protocols list --chronicle high-five --region na
pnpm cli contexts inspect high-five:base:na --json
pnpm cli contexts schema --json
```

Создание и изменение контекстов выполняются через `contexts create|update`
с `--file`, а согласованные изменения — через `batch`. UUID, `key`, `code` и
`releaseKey` новой записи выводятся из команды. `releasedOn: null` не заменяется
датой патчноута; отсутствие региона не размножает номера по всем колонкам.

Переход рабочего каталога описан в
[отчёте схемы 20](../../docs/research/regional-catalog-transition.md).

Команды запускаются из корня проекта. Нужны Node.js 24 и pnpm.

Для предметного редактирования используйте [CLI](../../apps/cli/README.md):
`pnpm cli protocols update`, `pnpm cli releases update`, `pnpm cli batch`.
Связанные изменения и удаления выполняйте одним пакетом с `--dry-run` перед
записью и `ifRevision` для защиты от конкурентных изменений. JSON-снимок вручную
не редактируется: после изменения SQLite выполните экспорт.

```bash
pnpm data:build
pnpm run database import
pnpm run database status
```

| Команда                     | Действие                                  |
| --------------------------- | ----------------------------------------- |
| `init`                      | Создать пустую базу с языками `ru` и `en` |
| `import`                    | Заменить базу полным снимком из `data/`   |
| `apply --file changes.json` | Применить атомарный пакет изменений       |
| `export`                    | Сохранить все таблицы в `data/`           |
| `status`                    | Показать состояние базы                   |

```bash
pnpm run database apply --file changes.json
pnpm run database export
```

Параметры: `--database` — SQLite-файл, `--input`/`--output` — каталог обмена,
`--json` — машинный результат. Относительные пути отсчитываются от каталога пакета.
Полная справка: `pnpm run database --help`.

## Пакет изменений

`changes.json` содержит `operations` и необязательный `ifRevision` — ревизию базы
для защиты от конкурентных изменений. Операции:

- `create`, `put` — полная запись `entry: { collection, key, kind, value }`;
- `update` — адрес `target: { collection, key, kind }` и изменяемые поля `patch`;
- `delete` — адрес `target`.

`kind`: `entity` для карточки, `implementation` для технической редакции.
Переводы передаются в `value.translations`, применимость редакции — в `protocolKeys`.
Массивы в `patch` заменяются целиком. Весь пакет проверяется и сохраняется одной
транзакцией. Точные контракты: [схемы данных](src/model/schema.ts) и
[программный API](src/api/database.types.ts).

## Экспорт

Каждая таблица получает папку, каждая строка — JSON-файл. Одиночный первичный ключ
задаёт имя файла; составной — первые 8 символов SHA-256, например `5b401a1c.json`.
Имена стабильны. При коллизии внутри таблицы экспорт завершается с ошибкой до
записи файлов. Импорт также поддерживает прежние имена `key-<полный SHA-256>.json`.

Пустые таблицы включаются в манифест. Содержимое `data/` обновляется экспортом.

## Разработка

Предметные чтения, фильтры и запись используют Drizzle Query Builder с типами колонок
из деклараций. Нативный SQL применяется для инспекции SQLite, восстановления структуры
и универсального табличного обмена. Транзакции используют одно соединение.

После изменения определений таблиц сгенерируйте SQL:

```bash
pnpm --filter @l2ce/database schema:generate
```

DDL генерирует Drizzle Kit; небольшой адаптер добавляет обязательный режим `STRICT`.
Генерация не создаёт историю миграций. Сборка проверяет соответствие `schema.sql`
декларациям, а открытие базы — соответствие таблиц и явных индексов текущей схеме.

Проверки:

```bash
pnpm data:build
pnpm --filter @l2ce/database typecheck
pnpm --filter @l2ce/database test
pnpm format:check
```
