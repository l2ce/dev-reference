# Представления справочника

`@l2ce/core` формирует продуктовые представления знаний для потребителей.
Хранение, предметные ограничения и запись принадлежат `@l2ce/database`.

## Чтение текущей базы

`ReferenceReader` из `@l2ce/core/reference` принимает проверенный предметный снимок схемы 19. Он копирует
основание чтения и индексирует применимость; последующие запросы не обращаются
к SQLite. CLI и MCP используют один и тот же контракт.

```ts
import { openDatabase } from '@l2ce/database'
import { ReferenceReader } from '@l2ce/core/reference'

const database = openDatabase({ readOnly: true })
try {
  const reader = new ReferenceReader(database.snapshot())
  const protocols = reader.protocols({ number: 152, locale: 'ru' })
  const documents = reader.read({
    protocol: '273',
    locale: 'ru',
    keys: ['packet:protocol-version', 'scenario:game-connection']
  })
} finally {
  database.close()
}
```

| Метод                      | Назначение                                                    |
| -------------------------- | ------------------------------------------------------------- |
| `protocols`                | Каталог с поиском по номеру, тексту, ветке, хронике и выпуску |
| `protocol`                 | Полный контекст одного точного протокола                      |
| `catalog`, `catalogRecord` | Ветки, хроники, выпуски и их выбранные переводы               |
| `knowledge`                | Список и поиск применимых знаний по выбранному языку          |
| `read`                     | До 50 пакетов, сценариев и статей одним снимком               |

Списки возвращают `items`, `total`, `nextOffset`, `revision`. Поиск нормализует
Unicode и учитывает заголовок, аннотацию и Markdown выбранного языка. Каталоговые
списки содержат краткие карточки; полные тексты читаются после выбора.

Для чтения знания нужен протокол. Карточка и профиль выбирают одну техническую
редакцию, затем выбирается перевод. Отсутствие карточки, применимости и перевода
имеет отдельный `availability`; другой профиль или язык не подставляются.
`status` исследования и `translationStatus` возвращаются независимо.

Markdown сохраняется исходным, включая директивы. Результат содержит читаемые ключи,
источники, вопросы и технические признаки. Полученные объекты являются копиями;
изменение вызывающим кодом не меняет основание последующего чтения.

Индексы и поиск работают в памяти полного предметного снимка. Пагинация ограничивает
размер ответа, но не означает SQL LIMIT. MCP переиспользует reader до обновления
поколения; CLI создаёт reader для одного вызова.

## Markdown-рендерер и сайт

`@l2ce/core/markdown` открывает независимый от хранения парсер директив
`markdownDirectives` и `renderMarkdown`. Web передаёт собственный resolver,
который разрешает ссылки и вставки через `ReferenceReader` текущего профиля
и языка; старый `createKnowledgeApi` для этого не используется.

Пакет также содержит `renderMarkdown`, `createKnowledgeApi` и проекции страниц
предыдущего документного представления. Они сохраняются для действующего кода
сайта и его тестов. Их схемы не заменяют модель базы 19; адаптация сайта к общим
записям и переводам выполняется отдельно.

Разрешение директив и оформление ссылок — ответственность представления и
приложения. База хранит Markdown буквально. Единый контракт источника импортируется
из `@l2ce/database/source`.
