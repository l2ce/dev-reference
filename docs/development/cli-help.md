# Контракт встроенной справки CLI

Справка — часть исполняемого контракта, а не сокращённая копия README.
Сведения, нужные для корректного вызова выбранного действия, находятся в CLI:
назначение, синтаксис, ключи, обязательность и умолчания, типовые ограничения,
результат, отсутствие данных, безопасность, ошибки и проверяемые примеры.
Источник предметной модели остаётся прежним: SQL и публичные схемы пакета базы.

## Источники и ответственность

Все пути ниже относительно `apps/cli/src/`:

- `help/catalog.ts` — дерево новых операций, сигнатуры, позиционные аргументы,
  наборы опций, правила со стабильными ID, последствия и соседние действия.
  `commands/interface-program.ts` регистрирует команды из этого реестра.
- `help/options.ts` — флаги, смысл, тип, choices, умолчания и парсеры параметров.
  Один объект используется при регистрации Commander и при рендере.
- `commands/definition.ts` — реальные схемы публичных значений, отношения,
  смысл полей и метаданные Markdown/файлов/поиска. `valueSchema` применяется
  предметным планировщиком, а не только документацией.
- `help/schema.ts` — JSON Schema операции и параметров, поля, условные ограничения
  батча по `op/key`. Непредставимые в обычном JSON Schema предметные проверки
  не выдаются за формальную проверку FK, фактов или состояния базы.
- `help/examples.ts` — args, буквальный stdin, существующие файлы, подготовка,
  ожидаемые результаты и получения `<version>/<cursor>`. Рендерер и тесты
  используют одни и те же шаги, не извлекают команды из вручную написанного текста.
- `help/legacy.ts` — явный адаптер прежних команд и DTO-имён. Старая замена
  массивов, `ifRevision` и каскад не называются новым `update/ifVersion/delete`.
- `help/document.ts` — полный выбранный документ и два согласованных представления.
  Поля и варианты уточняются по типу; JSON не подменяет вложенный узел корнем.
- `help/brief.ts` — явный краткий рендер того же контракта: параметры, поля,
  критичные правила и один основной пример с подготовкой. Полный режим не заменяется.
- `help/service.ts` — разбор справочного запроса без SQLite и stdin, группы без
  действия, рабочие сценарии и готовый следующий безопасный шаг диагностики.
- `commands/invocation.ts` — доступный launcher и POSIX-экранирование команд
  справки, продолжения и восстановления; выбранная база не теряется.
- `commands/diagnostics.ts` — предметные объяснения ошибок полей, включая
  различие карточки и редакции, без автоматического выбора редакции.
- `help/coverage.ts` — обход фактического Commander-дерева; отсутствие описания
  команды, позиции, ключа, примера или справочной ссылки считается ошибкой проверки.

## Контекст и навигация

```bash
pnpm cli help update --type releases
pnpm cli update release:example --help
pnpm cli help source add --type releases
pnpm cli source add release:example --help --format json
pnpm cli schema revision.add packet:example
pnpm cli schema locale.add
pnpm cli schema init
pnpm cli help update release:example --brief
pnpm cli schema create --type releases --brief
pnpm cli help source update --type releases --format json --structure-only
```

Адрес не обязан существовать. Тип не выводится из заголовка, языка или SQLite.
Без контекста выводится матрица различий, с контекстом — реальные применимые поля.
Значение `--description --help` остаётся данными и не становится справочным запросом;
`--` завершает разбор флагов. Форматы `--format json`, `--format=json`, совместимый
`--json` и `--pretty` не смешивают JSON с обычным текстом.

Корень перечисляет возможности и группы, группа — дочерние действия; полный
контракт листового действия не заменяется ссылкой на README, исходники или schema.
Schema — дополнительное системное представление, а не единственный способ изучения.

`--brief` сокращает только явно запрошенный текст справки/схемы. Критичные правила
берутся из основного реестра, подготовка примера не удаляется. JSON-структура и
JSON Schema остаются полными. `--structure-only` требует JSON-справку и исключает
дублирующее поле `data.help`, сохраняя полную `data.structure`; существующий JSON
по умолчанию не меняется. Эти режимы не запускают предметную команду, сочетание
`--brief --structure-only` отклоняется.

Готовые команды в справке, продолжении и `nextSteps` используют доступный launcher:
workspace — `pnpm --silent cli`, прямой Node.js — абсолютные пути, установленный
бинарник — путь запуска. Команды восстановления сохраняют `--database`, формат и
применимые язык/протокол. `edit` не сочетается с ограничивающим языком. Примеры
по-прежнему используют собственную базу `./example.sqlite`, не рабочую базу запроса.

Диагностика выбирает безопасное уточнение причины: список редакций/переводов,
источников, связей, языков либо каталог типа. Поля ошибки батча относятся к его
ошибочной операции. Для курсора предлагается запрос с теми же условиями, но без
курсора; уже прочитанный stdin заменяется явными адресами. Исполнение таких
команд, сохранение контекста и экранирование проверяются регрессионными тестами.
Ведущий дефис поискового текста сохраняется как позиционный аргумент после `--`,
не превращаясь в параметр CLI. Для stdin-выборки `--selection -` учитывается
единственный читатель stdin; пагинация требует файл, сохраняющий закреплённые редакции.

Текст успешной мутации показывает сохранённый токен версии рядом с исходным;
no-op сохраняет токен, dry-run не публикует будущую версию как сохранённую.

## Как добавлять возможность

1. Согласовать действительное поведение с предметным API. Новое поле знания
   не добавляется только ради примера справки.
2. Добавить `CommandSpec` и обязательные смысловые разделы. Для вложенного действия
   ID имеет вид `source.update`, сигнатура последнего уровня — `update <key>`.
3. Добавить или переиспользовать описание параметра с типом, choices/форматом,
   настоящим умолчанием, ограничениями и парсером. Техническое имя не заменяет смысл.
4. Для типозависимого ввода использовать реальные схемы и совместимость фильтров,
   не отдельный вручную синхронизируемый список флагов в тексте.
5. Добавить исполняемые примеры: минимум корректный вызов и типовой сценарий,
   для мутаций предпросмотр, для сложных действий альтернативы и значимый отказ.
   Все предусловия — явные setup-команды на новой отдельной базе.
6. Проверить значимые значения результата через CLI: буквальный `content`,
   `expect` по JSON-путям, ошибку, курсор или версию. Повторяемые примеры не
   используют рабочую SQLite и не наполняют канонический снимок.
7. Для нового ограничения добавить положительный и отрицательный регрессионный
   сценарий в `test/help*.test.mjs` либо предметные тесты CLI.

## Проверки

```bash
pnpm cli:help:check
pnpm typecheck
pnpm test
pnpm format:check
```

`cli:help:check` сначала собирает CLI, затем проверяет:

- все реальные новые и совместимые маршруты, включая корень и группы;
- все собственные параметры и позиционные аргументы;
- контексты всех допустимых типов, отсутствие чужих скалярных флагов;
- справочные связи, обязательные разделы, форматы, choices и умолчания;
- исполнимость публикуемых примеров в text/JSON и типовые мутации по всем типам;
- получение и применение курсоров/версий, неоднозначность, пустые области и rollback;
- валидность JSON Schema через Ajv и принятие/отказ на положительных/отрицательных пакетах.

`test/usability.test.mjs` дополнительно проверяет краткую справку всех маршрутов,
предметную диагностику и исполняет опубликованные команды продолжения/восстановления
на изолированных базах, в том числе с пробелами, кавычками и shell-символами.

Проверка встроена и в обычный `pnpm test`, поэтому отдельный необязательный запуск
не является единственным барьером CI. Добавление неописанной команды или флага
проверяется специальным тестом. Автоматическая полнота реестра не заменяет ревью
смысла формулировок и предметных гарантий.
