# CLI и MCP

Оба интерфейса используют общую предметную модель базы и `ReferenceReader` из
`@l2ce/core/reference`. Этот модуль зависит от чистых контрактов `@l2ce/database/model`,
а соединением SQLite владеет приложение. Это обеспечивает одинаковый выбор профиля, редакции и перевода.
Команды и параметры: [CLI](../../apps/cli/README.md), [MCP](../../apps/mcp/README.md).

## Продуктовое чтение

`ReferenceReader` строится из одного проверенного снимка схемы 21. Он хранит
собственную копию и индекс применимости `протокол / карточка → редакция`.
Ответы также являются копиями. Изменение исходного объекта или полученного ответа
не меняет последующие чтения этого reader.

- Каталог протоколов фильтруется по номеру, тексту, ветке, хронике, выпуску и региону.
- Вспомогательный каталог включает регионы, страны и региональные контексты выпусков.
  Контексты фильтруются по выпуску и региону, а порядок задаётся `order` до пагинации.
- Карточка протокола содержит точные `contexts`; общий список регионов вычисляется
  из них. `catalogRecord` и MCP `get_catalog_record` возвращают полные описания и источники.
- Чтение протокола использует точный ключ с необязательным `protocol:`.
- Поиск знаний требует профиль и учитывает только выбранный язык и явную применимость.
- Множественное чтение принимает до 50 логических ключей одним снимком.
- Ответ содержит ревизию основания чтения; списки дополнительно имеют `total` и `nextOffset`.
- Markdown возвращается исходным. Пробелы карточки, применимости и перевода различаются.

Чтение работает в памяти полного снимка. Пагинация ограничивает ответ, а не число
обрабатываемых SQL-строк. CLI получает новый снимок на команду; MCP переиспользует
reader до смены поколения. Самостоятельные запросы по обе стороны обновления могут
иметь разные ревизии, но один запрос никогда не смешивает поколения.

## CLI: агент действует, пользователь видит намерение

Основные команды начинаются с предмета: `protocols`, `packets`, `scenarios`,
`articles`, `branches`, `chronicles`, `releases`, `contexts`, `regions`, `countries`. Обычные операции используют короткие
коды и номера, UUID назначаются автоматически. Команды разделяют чтение документа
(`get` с протоколом), исследование данных (`inspect`, `revisions`) и запись
(`create`, `update`, `add-revision`, `update-revision`, `translate`, `delete`).

Запись проходит через единый API базы. `translate` подготавливает изменение только
нужного перевода, сохраняя остальные. Между исходным чтением и записью возможна
конкурентная правка, поэтому CLI передаёт `ifRevision` даже без явного флага:
в этом случае используется ревизия своего чтения.

`--dry-run` рассчитывает и проверяет изменение без сохранения. Отчёт записи содержит
действие, читаемые ключи, названия полей, число затронутых записей и ревизии.
Батчинг оставлен в форме полного JSON-пакета базы для сложной агентской работы.
Несколько связанных операций сохраняются одной транзакцией.

Человекочитаемый вывод — основной. `--json` даёт один структурированный ответ;
ошибки и диагностические сведения направляются отдельно. Чтение stdin происходит
только у команд, принимающих данные; удаление не читает ввод.

## MCP: только чтение знаний

Инструменты MCP не создают и не изменяют предметные записи. Все имеют
`readOnlyHint: true`. Команды ручной загрузки или обновления не публикуются как
инструменты. Запись в приватный кеш является внутренней задачей синхронизации.

```text
Репозиторий → проверка версии data/ → загрузка папки → импорт нового SQLite
                                                     ↓ проверка
Инструменты чтения ← ReferenceReader ← read-only активное поколение
```

### Выбор версии источника

Источник по умолчанию — Git-репозиторий L2CE Dev Reference и папка
`packages/database/data`. Сначала проверяется коммит выбранной ветки или удалённого
HEAD. При новом коммите Git запрашивает метаданные с `blob:none`; затем сравнивается
**tree hash папки данных**.

Этот хеш учитывает содержимое файлов, а не только число строк в манифесте.
Если изменился лишь README вне папки данных, checkout и импорт не выполняются.
При изменении tree hash выполняется sparse checkout `data/` из закреплённого коммита,
поэтому дальнейшее движение ветки не смешивает файлы разных версий.

Для локального режима разработки используется хеш путей и точных байтов файлов.
Он повторно проверяется после импорта: изменившийся во время операции источник
не становится активным поколением.

### Поколения и отказы

Новый снимок импортируется в отдельный SQLite-файл штатным механизмом базы.
После полной проверки он открывается read-only, создаётся новое представление
и атомарно сохраняется указатель кеша. Только затем переключается активный reader.
Уже полученные reader продолжают читать свой неизменяемый снимок.

Проверки запускаются автоматически по таймеру; одновременные попытки объединяются.
Сбой сети или невалидные данные оставляют прежнюю базу доступной. Статус сообщает
последнюю ошибку и время проверки. После перезапуска валидный кеш обслуживает
запросы сразу, а проверка источника выполняется в фоне. Без кеша первый импорт
должен завершиться успешно до запуска инструментов.

В статусе различаются `sourceHash` каталога и `dataRevision` предметного снимка.
Структурные переименования файлов могут изменить первый, сохранив второй.
Кеш изолируется по настройкам источника; исходный репозиторий и база разработчика
не изменяются. Sparse checkout принадлежит отдельному экземпляру MCP: процессы
с общим кешем не переключают рабочее дерево друг друга во время импорта.
Закрытие MCP прекращает таймер, закрывает соединение и удаляет свой временный
checkout после завершения выполняющейся синхронизации.

## Проверяемые гарантии

- [CLI](../../apps/cli/test/records.test.mjs): явные изменения, dry-run, конфликт ревизии,
  сохранение других переводов, атомарный пакет.
- [Общее чтение](../../packages/core/test/reference.test.mjs): одинаковые номера,
  отсутствие fallback, множественное чтение и неизменяемое основание.
- [Синхронизация MCP](../../apps/mcp/test/dataset.test.mjs): изменение содержимого,
  пропуск посторонних коммитов, закреплённый Git checkout, повреждённый снимок и offline-кеш.
- [MCP stdio](../../apps/mcp/test/stdio.test.mjs): только read-only инструменты,
  поиск, читаемые ключи и чтение знаний.
