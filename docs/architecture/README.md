# Архитектура L2CE Dev Reference

Этот раздел фиксирует принятые решения, границы компонентов и наблюдаемое
поведение проекта. Он служит основанием для изменения базы и разработки её
потребителей. Команды запуска находятся в [README проекта](../../README.md)
и [руководстве базы](../../packages/database/README.md).

## Назначение продукта

L2CE Dev Reference — справочник для разработчиков, работающих с обменом клиента
Lineage II с Login и Game Server. Основной сценарий:

**выбрать протокол и язык → найти пакет, сценарий или статью → прочитать Markdown.**

Протокол определяет технический контекст документации. Ветки, хроники и выпуски
помогают найти протокол и показать его принадлежность. Результат чтения включает
имеющиеся знания, источники, полноту исследования и открытые вопросы.

## Компоненты и ответственность

| Компонент                   | Ответственность                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| `packages/database`         | Предметные схемы, SQLite, проверка данных, чтение и запись, импорт и экспорт                           |
| `packages/database/src/cli` | Рабочий интерфейс наполнения: `init`, `apply`, `import`, `export`, `status`                            |
| `packages/core`             | Общее продуктовое чтение через `ReferenceReader`; отдельно — прежний Markdown-рендерер сайта           |
| `apps/web`                  | Статический Next.js-сайт: каталог, точные профили и Markdown на ru/en через ReferenceReader            |
| `apps/mcp`                  | Только поиск и чтение; автоматическая синхронизация приватного SQLite-кеша из Git                      |
| `apps/cli`                  | Предметный терминальный интерфейс агента: чтение, создание, редактирование, переводы и пакетная запись |

База возвращает исходный Markdown и предметные связи. Разрешение директив,
выбор языка текста и построение ссылок принадлежат слою представления.
Оформление URL и формат ответа принадлежат конкретному приложению.

```text
Исследовательский агент → CLI базы → проверка и запись → SQLite
                                                      ↕ импорт / экспорт
                                                    data/ ↔ Git

SQLite → API базы → представление выбранного протокола и языка → сайт / MCP / CLI
```

Реализованный контракт базы — схема 19 с общими сущностями и отдельными переводами.
CLI и MCP используют `ReferenceReader` этой модели. Веб-приложение на Next.js
читает SQLite при сборке, сохраняет выбранный профиль и язык и экспортирует HTML
для GitHub Pages. Прежнее приложение
на Docusaurus удалено; старый Markdown-рендерер в `packages/core` остаётся отдельно.
Дев-редактор Markdown предусмотрен как следующий потребитель CLI записи.

## Основания решений

| Решение                                            | Причина                                                                                   |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Протокол имеет самостоятельную идентичность        | Номер протокола и название хроники не различают все клиентские контексты                  |
| Знание имеет карточку и технические редакции       | Один смысл сообщения сохраняется при различиях его реализации                             |
| Применимость перечисляется явно                    | Совпадение номера или соседство выпусков не доказывает совместимость                      |
| Технические данные общие, тексты локализованы      | Перевод не должен создавать другой опкод или другую применимость                          |
| Основное содержимое — Markdown                     | Неполные знания можно добавлять без предварительного моделирования всех полей и состояний |
| Источники принадлежат конкретному переводу         | Ссылки обычно подтверждают отдельную предметную реализацию и почти не переиспользуются    |
| SQLite хранит факты и связи, JSON сохраняет снимок | Целостность проверяется в одной модели, а изменения доступны в Git                        |

Исторические исследования с источниками находятся в [research](../README.md#исследования).
Они обосновывают решения, но не заменяют действующие контракты. Моки и тестовые
fixtures проверяют выразительность модели; историческая достоверность знаний
устанавливается по источникам и исследованию клиента.
